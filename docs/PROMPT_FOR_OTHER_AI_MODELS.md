# Safe-Navi continuation prompt

Use this prompt when handing the repository to another coding model:

> You are continuing the Safe-Navi Android project at `https://github.com/Aniket-Nikam/Safe-Navi`. First inspect the repository, `README.md`, and `docs/IMPLEMENTATION_PLAN.md`; run the existing unit tests and debug build before editing. Preserve the working Java/XML Android architecture and the distinction between unverified citizen reports and government-verified hazards. Do not claim synthetic data is live or train a fake ML model. Keep the deterministic, explainable risk engine as the production baseline unless real labelled data is supplied. Implement the next requested feature end-to-end with accessible UI, repository/domain separation, deny-by-default authorization, audit history, tests, and documentation. Never expose API keys or let client-side role strings authorize government actions. When adding route drawing, use a legitimate routing provider, show required attribution, evaluate returned route alternatives against verified hazards, and retain fastest/balanced/safest choices. Finish by running `testDebugUnitTest` and `assembleDebug`, then report exactly what works, what configuration is required, and what remains incomplete.
